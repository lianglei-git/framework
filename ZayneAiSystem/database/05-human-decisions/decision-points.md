# 数据层的人类决策点

数据层的决策门槛是全系统最高的——表结构变更牵扯存量数据，回退成本可能是无穷大
（数据删了就是删了）。分两级：

## 一、破坏性变更（最高门槛，必须完整呈报）

删表、删列、改列名、改类型、删索引。agent 必须先提交**影响评估**再等批准：

1. 受影响的模块清单（依据 schema.llms.txt 的 written_by / read_by，不靠印象）；
2. 存量数据处理方案（迁走？丢弃？转换？各是多少量级）；
3. 回滚方案——如果没有（多数删除操作没有），明确写"此操作不可回滚"；
4. 执行窗口建议（大表操作是否锁表、是否需要低峰执行）。

用户批准后才允许写 migration，并在需求文档决策记录留痕。
**agent 永远不得以"这列看起来没人用了"为由自行删除任何东西。**

## 二、加法变更（轻量确认）

建新表、加可空/带默认列、加索引：

- agent 给出表设计（或列定义）与一句话理由，用户点头即可动手。
- 唯一例外要升级为完整讨论的：判重发现与现有表字段重合过半仍坚持新建
  ——这本质是数据模型的分歧，值得辩论清楚再动手。

## 明确不需要问人的事

- migration 文件命名、注释格式（规范已定）。
- 字段类型选择（遵循表设计约定即可）。
- schema.llms.txt 的维护（schema 已定）。
- 本地/测试库的实验性建表（不进版本库的不算数）。
