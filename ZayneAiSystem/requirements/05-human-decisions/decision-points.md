# 需求层的人类决策点

需求层是所有领域里**人的占比最高**的一层——因为"不做什么"取决于资源与意图，
这个信息只在人脑里，任何调研都替代不了。但也仅限以下三件事：

## 一、收敛（砍需求、定 Non-goals）

- agent 负责把可能性空间铺开并给出取舍建议，最终砍哪些**必须由人决定**。
- agent 不得以"行业都这么做"为由代替用户保留某个需求点。

## 二、确认（draft → confirmed）

- 需求文档从草稿转为契约的唯一通道。确认动作意味着：
  此后 agent 会以该文档为开发依据、以其 AC 为测试依据，不再逐条请示。

## 三、变更已确认的需求

- confirmed 之后改范围/AC，一律先问、留痕、再改。
- agent 发现实现过程中 AC 不合理（做不到、自相矛盾、成本远超预估）时，
  **停下上报并给出修改建议**，不得静默按自己的理解偏离文档。

## 明确不需要问人的事

- 调研查什么、查多广（发散阶段 agent 自主）。
- AC 的措辞打磨（只要满足可判定性检查）。
- 文档格式、索引维护（schema 已定）。
- draft 阶段的任何修改。
