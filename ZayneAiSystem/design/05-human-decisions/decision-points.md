# 设计层的人类决策点

设计层大部分决策已被 token 和模式吃掉，剩给人的按影响面分三档：

## 一、参照设计语言的选定与更换（最高门槛，与数据层破坏性变更同级）

- 项目启动时选一次；更换 = 全站视觉重刷，必须完整讨论
  （为什么换、迁移成本、是否值得）。
- agent 可以在启动时给候选对比（各参照的气质、组件生态、与产品调性的匹配），
  **选哪个必须人拍板**——这是纯品味决策，AI 没有品味。

## 二、Token 的增改（完整呈报）

- 改既有 token 值（如主色）：影响所有消费方，呈报影响面后再改。
- 加新 token 档位（新颜色、新间距档）：呈报"为什么现有刻度不够"——
  多数时候是设计偷懒的信号，默认答案应该是"用现有档位"。
- 原始层调色板变动同上。

## 三、模式的新建与修改（轻量确认）

- 新模式：版式一句话 + 组件构成，点头即动手，落地后登记索引。
- 改既有模式：说明 applied_in 里哪些页面会跟着变，确认后统一改
  ——禁止只改一处造成同模式页面分叉。

## 明确不需要问人的事

- 用既有模式 + 既有 token 组装页面（这是 agent 的日常，全部自主）。
- 批评环自查中当场可修的问题（对比度、目标尺寸、间距归位）。
- 文案措辞的微调（错误提示说人话化）。
- patterns.llms.txt 的维护（schema 已定）。
