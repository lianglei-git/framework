# L5 人的决策点

人是系统里最贵的执行者，所以到达这一层的事项必须最少。
**只有以下两类事需要问用户，其余一切由 L1–L4 消化，不得上报。**

## 一、提升为公共资产（不可逆的抽象决策）

触发条件（由 L4 流程规则探测，依据是 L3 索引，不做全库扫描）：

| 场景 | 信号 | agent 的动作 |
|------|------|--------------|
| 公共组件提取 | 索引中 ≥2 个条目职责相似，或某组件 uses>=2 且横跨多业务 | 暂停，给出候选与建议接口，问是否开子 agent 提取到 shared |
| 公共 store 提取 | 两个业务 store 的 state/actions 字段重合过半 | 暂停，给出重合字段清单，问是否开子 agent 按业务提取 |
| biz store 升 global | 某 biz store 被 ≥2 个业务的页面引用 | 暂停，说明引用方，问是否提升 |

用户确认后才允许开子 agent 执行提取；提取完成后子 agent 必须同步更新两份索引。

**为什么这类要问人**：抽象一旦发布就有依赖方，回退成本远高于建立成本；
而且"该不该抽象"依赖业务未来走向的判断，这个信息只在人脑里。

## 二、规则修订

- 增/删/改任何层级的规则，按 `00-meta/constitution.md` 流程走，最终由人拍板。
- agent 可以**提议**修订（尤其在发现自己反复与某条规则摩擦时，参照元规则二），
  但不允许自行修改规则文件。

## 明确不需要问人的事（防止决策点膨胀）

- 组件放哪一层（有 directory-spec 判断标准）。
- store 是 global 还是 biz（拿不准默认 biz，有默认值就不用问）。
- 复用现有组件还是扩展它（复用优先原则已定）。
- 索引条目怎么写（schema 已定）。
