# 元规则（constitution）

规则系统和代码一样会腐化。本文件约束「规则本身」，是整个内核里唯一凌驾于其他规则之上的文件。

## 元规则一：每条规则必须声明它防止什么问题

- 新增任何规则（lint 规则、流程规则、schema 字段）必须填写 `prevents` 字段（见 `rule-template.md`）。
- 当 `prevents` 描述的问题不再存在（技术栈变了、业务形态变了），该规则**必须删除**，不留"以防万一"。
- 规则库只做减法审查，不做无脑累加：每次新增一条 L4 流程规则时，先自问能否下压到 L1/L2；能压则不新增。

## 元规则二：agent 系统性绕过某条规则时，优先怀疑规则错了

- agent 反复绕过、变通、或在遵守时产出明显别扭的代码，是**规则与实际开发摩擦过大**的最诚实信号。
- 处理顺序：先审规则（是否过时、是否层级放错、是否表述含糊），再审 agent。
- 禁止的应对方式：把同一条规则用更强硬的措辞再写一遍。

## 元规则三：L4 流程规则有总量预算

- 自然语言规则消耗每次对话的上下文，遵守率与规则数量成反比。
- 预算：**每个领域**的 L4 目录下同时生效的规则文件不超过 5 个，单文件不超过 60 行。
- 超预算时必须先删或下压旧规则，才能加新规则。

## 元规则四：修订留痕

- 规则的增、删、改在本文件末尾的 Changelog 记一行：日期、动作、原因（一句话）。
- 这份 Changelog 就是规则系统的病历，复盘"为什么当初这么定"时唯一可信的依据。
