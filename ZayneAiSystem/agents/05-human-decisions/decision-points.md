# Agents 领域的人类决策点

## 一、扩编（最高门槛）

- 新增任何**常驻**角色（哪怕看起来很有用），必须完整讨论：
  它需要判断力吗？（不需要 → 做成脚本进 CI，不入编）
  它的职能现有角色真的承担不了吗？协调成本按平方涨，值得吗？
- 默认答案是**不扩编**。历史上被取消的四个角色（监察/回归/测试/常驻审理）
  的教训写在 `agent-roster.md`，扩编讨论前先重读。

## 二、评审争议的裁决

- 执行 agent 与 review agent 对 must-fix 意见相持不下时，由人裁决。
- 裁决结果若暴露的是规则含糊（两边都有理），按元规则一修订对应规则，
  让下一次同类争议不再发生。

## 三、提取类子 agent 的批准（承接各领域 L5）

- 公共组件/store/表复用的提取派发，批准动作在各领域 05 层已定义，
  此处只补一条：**批准记录必须可追溯**（写入需求文档决策记录或
  delegations.llms.txt 的 approved_by_decision 字段），口头批准不算数。

## 明确不需要问人的事

- 符合三条判据的调研类/机械改造类子 agent 派发（不涉公共资产提取）。
- review agent 的常规执行与 nit 级意见的取舍。
- delegations.llms.txt 的维护（schema 已定）。
