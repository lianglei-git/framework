# Agent 编制章程

本领域的不可逆资产是**编制本身**：agent 数量每加一个，协调复杂度按平方增长，
且每道 agent 边界都损失一次上下文。编制只做减法审查，扩编是 L5 决策。

## 判断力之尺（全领域唯一判据）

> **一个环节需不需要 agent，只看它需不需要"判断力"。
> 机械可判定的检查用确定性工具，永远不要用 LLM。**

LLM 检查员与被它检查的 LLM 有同样的失败模式（遗忘、幻觉、上下文漂移）——
让它盯规则等于让近视眼互相检查视力。规则合规交给 lint/CI，agent 只做需要判断的事。

## 编制表（全部在编角色，无常驻官僚）

| 角色 | 数量 | 职责 | 明确不做 |
|------|------|------|----------|
| 执行 agent | 1（主对话） | 按各领域五层规则开发；写测试是分内事 | 自我豁免终止条件 |
| 子 agent | 按需，用完即散 | 边界清晰的隔离任务：公共组件/store 提取、独立调研、批量机械改造 | 长期存续；接手模糊任务 |
| review agent | 每次交付前 1 遍 | 只找 lint 查不出的问题：逻辑漏洞、边界条件、设计不当 | 检查规则合规（那是 lint 的事） |
| 确定性 CI | 常驻 | lint、测试、checksum、索引同步等全部机械闸门 | — |

## 明令取消的角色（及其去向）

| 曾设想的角色 | 为什么取消 | 职能去向 |
|--------------|-----------|----------|
| 监察 agent | 用概率系统盯确定性规则，又贵又不可靠 | L2 lint / CI |
| 回归 agent | 回归测试完全机械：跑套件，过或不过 | CI 测试闸门 |
| 测试 agent | 测什么由需求 AC 客观决定，写测试是执行 agent 分内事 | 执行 agent 的终止条件 |
| 审理 agent | 方向对但形态错：不是常驻官员 | review agent（交付前单遍） |

## 子 agent 任务书（必须自包含）

子 agent 看不到主对话的上下文，任务书是它的全部世界。缺项不得派发：

```yaml
goal:        一句话目标 + 完成的可判定标准
inputs:      必读文件清单（相关 *.llms.txt、涉及源码路径、适用的领域规则文件）
constraints: 适用的边界规则（哪层不能碰、哪些 API 不能改）
deliverables: 产出物清单（代码、更新哪些索引条目）
termination: 终止条件（对应领域的终止清单 + 本任务特有项）
non_goals:   明确不做什么（防止子 agent 好心越界）
```

## review agent 的工作契约

- 输入：本次变更 diff + 关联的 FEAT 文档（AC 是评审基准）。
- 只报告**需要判断力才能发现**的问题；lint 能查的不报（重复报警稀释注意力）。
- 产出分级：must-fix（逻辑错误/数据风险）/ should-fix（边界缺失）/ nit（可忽略）。
- 执行 agent 对 must-fix 必须处理（修复或有理有据地反驳）；争议不下 → 人裁决。
